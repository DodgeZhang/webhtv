## 3. 不通过的部分：TV 横向间距 20dp

### 3.1 标准与 token

设计文档 §6（line 610–612）、§(line 705)、§(line 1173) 三处都要求 **TV 横向列表项间距 20dp**。
设计系统为此定义了 token：

```
app/src/main/res/values/webhtv_dimens.xml:11
    <dimen name="webhtv_size_tv_card_gap">20dp</dimen>
```

### 3.2 该 token 从未被引用

```
grep -r webhtv_size_tv_card_gap app/src   →  1 处命中，就是它自己的声明
```

**只声明、没接线。** 这与设计系统此前审计发现的 `webhtvColorScrim` /
`webhtvColorOverlayDark` / `webhtvColorOverlayLight`「只声明、从未赋值」是同一类缺陷。

### 3.3 实际间距是各调用点硬编码的 8/10/12/16dp

| 位置 | 值 |
|---|---|
| `HomeActivity.java:517/518/519` | `new CustomRowPresenter(16)`（VodPresenter / FuncPresenter / HistoryPresenter 三行） |
| `HomeActivity.java:522` | `typeRecycler.setHorizontalSpacing(ResUtil.dp2px(16))` |
| `TypeFragment.java:159` / `:160` | `CustomRowPresenter(16)` / `CustomRowPresenter(8)` |
| `CollectFragment.java:82` | `CustomRowPresenter(16)` |
| `VodActivity.java:156` | `recycler.setHorizontalSpacing(ResUtil.dp2px(16))` |
| `adapter_episode_card.xml` | `android:layout_marginEnd="12dp"` |
| `SiteDialog.java:253`、`RestoreDialog.java:65`、`LiveDialog.java:65`、`HistoryDialog.java:95`、`CastDialog.java:120`、`DohDialog.java:51` | `new SpaceItemDecoration(…, 16)` |
| `VideoActivity.java:1737-1799`、`:3831`、`:3908` | 8dp / 12dp |

`CustomRowPresenter.java:70` 是 TV 行间距的唯一落点：
`grid.setHorizontalSpacing(ResUtil.dp2px(spacing))`，`spacing` 由各调用点传入。
**没有任何调用点传 20dp，也没有任何调用点读该 token。**

反查确认：leanback 里 `20dp` 确实出现（40 处），但**全部**是 padding / margin / 图标尺寸 / 圆角，
**没有一处**用于卡片横向间距。

### 3.4 设备实测

`uiautomator dump` 得到「更新推荐」行 5 张卡的精确 bounds（1920×1080 像素）：

```
x = 48, 419, 790, 1161, 1532     每张宽 339
相邻间距 = 419-387 = 790-758 = 1161-1129 = 1532-1500 = 32px
行容器宽 1824（x=48 起），5×339 + 4×32 = 1823 ✓
```

**实测间距 32px = 10.67dp**（density 3.0），既不是 20dp（应为 60px），也不等于任何调用点声明的 16dp。

### 3.5 承载该标准的测试名不符实

```
app/src/test/java/com/fongmi/android/tv/ui/style/UiLayoutSourceTest.java:33-39
    public void tvCardsUseTheSharedCardGapTokenAndRoundedFamily() throws Exception {
        String card = Files.readString(Path.of("src/leanback/res/layout/adapter_episode_card.xml"), …);
        assertTrue("TV episode cards must keep the shared rounded family",
                card.contains("app:cardCornerRadius=\"@dimen/webhtv_card_radius_default\""));
        assertFalse("TV episode card colours must be token-only", card.matches("(?s).*#[0-9A-Fa-f]{6,8}.*"));
    }
```

方法名含 `GapToken`，但**函数体没有断言任何间距值**——只检查圆角 token 与「无硬编码色」。
所以设计文档两处对它的描述都不成立：

- §19.3（line 1435）：「卡片比例、**TV 20dp**、安全区、焦点/状态、无未豁免固定色」
  → 实际只覆盖「部分卡片比例」与「无硬编码色」；
- §21（line 1180）：「列表/卡片几何测试（新增 `UiLayoutSourceTest`）断言比例、**20dp TV 间距**、2:3/16:9」
  → 同上。

### 3.6 首页卡片没有声明比例

`adapter_vod.xml`（leanback 首页「最近观看 / 更新推荐」卡片）根节点是
`wrap_content × wrap_content`，图片只声明了 `android:layout_height="80dp"`，
**没有声明任何比例**。设备实测：

```
最近观看卡片：RelativeLayout 339×547，其中 ImageView 339×452  →  3:4
```

3:4 既不是设计文档 §(line 611)「海报 2:3、横向内容 16:9」中的任何一种。

## 5. 修复建议（需单独授权）

### 5.1 最小可用修复（建议范围）

1. **接线 token**：把 TV 卡片行的横向间距改为读 `@dimen/webhtv_size_tv_card_gap`，
   落点集中在 `CustomRowPresenter` 的调用方：
   `HomeActivity.java:517/518/519`、`TypeFragment.java:159`、`CollectFragment.java:82`，
   以及 `HomeActivity.java:522`、`VodActivity.java:156` 的 `setHorizontalSpacing`。
2. **卡片布局**：`adapter_episode_card.xml` 的 `layout_marginEnd="12dp"` → `@dimen/webhtv_size_tv_card_gap`。
3. **补测试**：`UiLayoutSourceTest` 新增对间距的真实断言（例如断言上述布局/调用点引用该 token），
   并**修正方法名或补上断言**，使 §19.3/§21 的描述成立；否则应同步下调文档描述。
4. **首页卡片比例**：给 `adapter_vod.xml` 的图片声明比例（2:3 或按实际内容类型），或明确豁免并记录理由。

### 5.2 风险

- 16dp → 20dp 会改变 TV 每行可见卡片数量与整体密度，属**可见的视觉变更**，
  需要重跑 C-T 与 B-T-D 两行，并抽查 C-M/D-T 相关页面是否有溢出或裁切。
- 因此**不建议**顺手改；应按独立单元实施，独立提交、独立 recovery tag。

## 6. 局限

1. 只覆盖 leanback 首页与其导航行、卡片行；`VodActivity`、`VideoActivity`、各弹窗的间距只做了**源码核查**，
   未逐页实机取证。
2. 实测间距 32px 与源码声明的 16dp（=48px）不一致，**来源未定位**：可能是 `HorizontalGridView`
   的 spacing 与 item 宽度共同作用，或 item 视图宽度并非其可见宽度。
   这不改变结论（32px 既非 20dp 也非 16dp），但修复前应先确认该落点，避免改了不生效。
3. 设备是 1920×1080 / 480dpi（= 640×360dp）的模拟器，而设计文档的 TV 基准是 **960×540dp**；
   dp 数值可直接比较，但"每行几张卡"这类布局观感不能直接外推到真机 TV。
4. 本行未做 D-pad 全量可达性遍历。
