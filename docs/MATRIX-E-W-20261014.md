## 2. 管理页：浅/深一致（通过）

### 2.1 渲染证据

用无头 Chrome 在浅色与深色两种 `prefers-color-scheme` 下渲染真实页面（`http://127.0.0.1:9978/m`）：

| 文件 | 说明 |
|---|---|
| `E-W-01-manage-light.png` | 浅色：白/浅灰底、深色字、蓝色主按钮 `上传文件` |
| `E-W-02-manage-dark.png` | 深色：黑底、浅色字、浅蓝主按钮 |

两态**布局一致**（顶部 WEBHTV/管理页面 + 本机·远端切换、文件管理卡片、底部
`文件/同步/登录态/站点/Proxy/接口/搜索/推送` 导航），仅配色切换。

### 2.2 token 逐项对照（决定性证据）

`ui.css` 自带完整 token 表，浅色在 `:root`、深色在 `@media (prefers-color-scheme: dark) :root`。
把两边变量与应用 `app/src/main/res/values{,-night}/webhtv_tokens.xml` 逐项比对：

| token | ui.css 浅色 | 应用浅色 | ui.css 深色 | 应用深色 |
|---|---|---|---|---|
| `primary` | `#0B57D0` | `#0B57D0` ✓ | `#A8C7FA` | `#A8C7FA` ✓ |
| `surface` | `#F8FAFD` | `#F8FAFD` ✓ | `#101418` | `#101418` ✓ |
| `surface-container-high` | `#E7E8EF` | `#E7E8EF` ✓ | `#2A2F34` | `#2A2F34` ✓ |
| `on-surface` | `#1A1C1E` | `#1A1C1E` ✓ | `#E2E2E9` | `#E2E2E9` ✓ |
| `secondary-container` | `#DFE2E6` | `#DFE2E6` ✓ | `#44474A` | `#44474A` ✓ |
| `on-surface-variant` | `#44474F` | `#44474F` ✓ | `#C4C6D0` | `#C4C6D0` ✓ |

**两种模式下逐项完全一致。** 管理页判定：**通过**。

> 注：渲染出的页面当时处于「页面已关闭」的**变暗态**（实测背景 `#A7A7AA` 而非 `#F8FAFD`），
> 所以**没有**用像素值去比 token，而是用 CSS 变量表比对——后者不受该状态影响，更可靠。

## 3. WebHome 与 reader：静态结构一致（通过），设备渲染未取证

### 3.1 这两个页面不硬编码 token

```
eclipse.html        : 0 个硬编码 --webhtv-* hex
eclipse-detail.html : 0 个硬编码 --webhtv-* hex
reader.html         : 0 个硬编码 --webhtv-* hex
```

它们把 `--webhtv-*` 当作**与原生桥的接口变量**，再映射到自己的样式变量：

```
eclipse.html:156   --webhtv-primary: var(--eclipse-color-1);
eclipse.html:158   --webhtv-surface: var(--eclipse-color-3);
eclipse.html:520-  primary: '--webhtv-primary',  surface: '--webhtv-surface', ...
```

页面自身样式使用本地变量族（实测使用次数）：

| 页面 | 本地变量族 | `var()` 使用 |
|---|---|---|
| `eclipse.html` | `--eclipse-*` | 58 |
| `eclipse-detail.html` | `--eclipse-detail-*` | 105 |
| `reader.html` | `--reader-*` | 52 |

即结构是「原生 `WebHomeThemeBridge` / `WebThemeTokenBridge` 写入 `--webhtv-*` → 页面映射到本地变量 → 样式消费」，
**没有**"只声明不消费"的死 token。

### 3.2 未取证的部分

**这两个页面的设备渲染证据本次没有取到**：

- WebHome 只在站点带 `homePage` 时出现，而 5559 上的配置源（`木偶[盘]`）走的是原生卡片网格，没有 WebHome；
- reader 需要 `novel://` 协议的小说/漫画站点（`NovelRouter`），当前源里没有。

因此「浅/深一致」在这两个面上只完成了**静态结构**层面的验证；渲染层面记为未取证。

## 4. 远程失败页面回退（逻辑层通过）

`WebThemeManifestLoader` 实现了缓存回落与回滚，`WebThemeRuntimeDiagnostics` 有 `FALLBACK` 诊断码。

```
./gradlew :app:testMobileArm64_v8aDebugUnitTest --tests 'com.fongmi.android.tv.web.*'
→ BUILD SUCCESSFUL in 23s
```

该套件里与本行标准直接相关的：

| 测试 | 覆盖 |
|---|---|
| `WebThemeManifestRollbackTest` | 清单回滚 |
| `WebThemeManifestLoaderTest` | 加载失败 → 缓存回落 |
| `WebThemeManifestHttpTest` | HTTP 取用 |
| `WebThemeManifestConditionalCacheTest` / `WebThemeManifestDiskCacheTest` | 条件缓存 / 磁盘缓存 |
| `WebThemeRuntimeDiagnosticsTest` | `manifest_cache_fallback` / `fallback` 诊断 |
| `WebHomeThemePolicyTest` / `WebHomeThemeBridgeTest` / `WebThemeTokenBridgeTest` | token 只读、schema/范围校验、失败不写原生 |

**逻辑层判定：通过。** 但"远程失败"没有在设备上真实制造过（未断开远端、未投毒 manifest），
所以**设备层的回退表现记为未取证**。

## 6. 局限

1. 管理页的渲染是在 **PC 的无头 Chrome** 里做的（该页本就是给外部浏览器用的），
   不是在设备 WebView 里渲染的。
2. 渲染时页面处于「页面已关闭」变暗态，故未用像素比对 token（§2.2 注）。
3. WebHome / reader 只做了静态结构验证，未取设备渲染证据（§3.2）。
4. "远程失败"只跑了单元测试，没有在设备上真实制造失败。
5. 未验证 TV（leanback）侧的 WebView 表现；本行设备是 mobile。
