## 3. 不可判定的部分：详情页

§20.2 的 D-T 场景是「详情 + 播放」。本次**只覆盖了播放**，详情页无法到达：

```
VideoActivity.java:761-765
    public static void startSkippingDispatch(..., TmdbItem tmdbItem, ...) {
        if (tmdbItem == null && shouldOpenLegacyTmdbDetail(key, id, cast)) {
            TmdbDetailActivity.start(activity, key, id, name, pic, mark, null,
                                     Setting.getDetailOpenMode(), searchKeyword);
            return;
        }
```

`TmdbDetailActivity` 只在 `shouldOpenLegacyTmdbDetail(...)` 成立时打开，即需要 **TMDB 类型的站点**。
当前配置源（`buye-0`）不是 TMDB 类型：

- 首页卡片点击走 `HomeActivity.java:1080-1083` → `VideoActivity.start(...)`，直接进播放；
- 从播放器按 BACK，`mCurrentFocus` 直接回到 `HomeActivityCurrent`，**没有经过详情页**；
- `TmdbDetailActivity` 未导出，`am start` 会被拒（同 `MATRIX-B-T-D-20261014.md` 的做法）。

**因此本行不能判为完整通过。** 按约定记为「不可判定」，不硬凑结论。
补齐需要换一个 TMDB 类型的配置源（或 `detailOpenMode` 允许的站点）。

## 4. 回归核查（针对 `fad60a9b1e6` 的 C-T 修复）

C-T 修复改了 TV 卡片行间距与 `adapter_episode_card.xml` 的 `layout_marginEnd`（12dp → 20dp）。
后者是**播放器选集**用的布局，需要确认没有引入双重间距：

- `VideoActivity.java:3908` 的 `SpaceItemDecoration(spanCount, 12)` 加在
  **`updateUpstreamNativeEpisodeGridViewport()`** 里，即**原生列表模式**的选集网格；
- `adapter_episode_card.xml` 只在 **TMDB 卡片模式**使用
  （`mEpisodeGridAdapter.setUseTmdbCard(useTmdbCards)`，`VideoActivity.java:3604`）；
- 两种模式互斥（切换时会 `clearEpisodeGridDecoration()`，`VideoActivity.java:2538`）。

**结论：不存在 12+20 的双重叠加。** 卡片模式下的横向间距现在正好是 20dp（token 值）。
未在设备上触发 TMDB 卡片模式（见 §5.2），这一点是静态判定的。

播放器 OSD 本身未被本次改动触及；`D-T-01..08` 的渲染与焦点行为均正常。
